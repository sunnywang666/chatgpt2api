## 工作台账号与个人程序密钥

账号授权与程序 Key 分开：账号录入、授权保存和刷新沿现有账号入口；应用只使用普通程序 Key，不取得上游登录凭据，也不需要池管理员密钥。既有工作台访问权限与账号管理权限不因此扩大。

在本人已有访问权限的工作台「ChatGPT / Codex → 密钥与 CLI」中，为目标应用创建并命名 Key，选择它要使用的 Chat／Codex 端。完整 Key 仅在创建响应中返回，私密保存到目标应用的环境配置；列表只显示元数据，不能找回完整秘密。不要把真实 Key 放进“复制给 AI 配置”、聊天、日志或代码。

Key 的名称只需在同一使用者、同一角色的记录中区分；不同使用者可以都叫“工作流”，不会互相占用名称或默认编号。内部无归属的旧 Key 保留自己的名称范围；不迁移、不认领旧 Key。名称不是鉴权身份，查询、修改和撤销仍按原 Key ID 与归属校验。撤销保留记录、关闭后续鉴权，不删除旧任务或改动已受理任务；另一把同名 Key 不受影响。已撤销名称仍保留，不会通过同名创建隐式复活旧 Key。

账号额度响应中的 `remaining` 可能是最后一次成功读取的历史值。只有 `state=observed` 才表示通过现有五分钟新鲜度检查的有效观测；有值但已过期、调用后待刷新、缺失或异常时间时为 `stale`，读取失败为 `read_failed`，没有有效额度数值为 `unknown`。真实零不改成未知，未知不伪造为零。刷新取得新的有效观测后可重新显示 `observed`；这段只说明观测投影，不将它冒充额度恢复后自动调度已经验收。

### 本人账号的刷新与启停

本人账号 HTTP 入口现在复用公司池已有的刷新及启停实现，不复制账号、不建立第二套刷新器。本人身份与原账号行 ID 先核对，再使用该行的稳定内部引用；响应仍是本人的账号视图。不存在、无归属或重复的账号行不能被任意选择，公司池引用不能代替个人行 ID。刷新过程中不持有全池锁；返回前再次核对原归属和引用。

刷新只读取已经保存授权的 Chat／Codex 端；没有 Codex 授权时不凭 Chat token 强行读取 Codex。沿用已有账号身份核对、凭据版本条件写入和相同目标刷新合并，旧凭据的迟到观测不能覆盖替换后的凭据状态。刷新返回 HTTP 200 仅表示取得当前账号视图，应继续读取各端的 state；读取失败保留旧额度和失败状态，不伪报为两端刷新成功。

重复启用或停用是无变化操作，不清空额度、不改写观测时间。真正重新启用时保留最后的额度证据，仍等待成功刷新后再解除停用状态；不把点击启用当作上游新增额度。保存失败沿原写入器返回失败，不绕过持久化处理。此处只修本人 HTTP 入口；未改旧服务方法的其他内部调用路径。

管理桥接的成功响应增加 private, no-store，包括账号、一次性 Key、授权会话等；这不取代原鉴权和工作台同源校验，也不保证调用程序从未把秘密写入自身日志。

C01/C02 候选补充命名、观测一致性与本人入口复用，没有改变同会话顺序、同账号多会话并行、槽位、归档、UNKNOWN 处理或生产参数。回归用例随源码提供；按当前实施顺序，待能力和消费者补齐后统一执行，不把语法检查算作功能测试。完整授权、凭据持久化、工作台普通角色交互及额度恢复后的自动调度仍分别保留验收义务。
